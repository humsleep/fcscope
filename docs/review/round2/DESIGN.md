## 0. 판정

**아직 승인하지 않는다. 남은 must-fix는 3건이고, 셋 다 작은 수정이다.**

1라운드 must-fix 11건 중 10건은 캡처로 해결을 확인했다. 나머지 1건(M4 BEST)은 색과 중복은 고쳐졌지만, 접힌 원래 자리 아래에 답글이 주인 없이 매달리는 새 문제가 생겼다.

이번 라운드에서 앱이 한 단계 올라섰다.
- 홈: 검색창이 하나가 됐고, S 마크 워드마크가 들어갔다.
- 매치·VS: 상대 = 중립색, 앞선 값 = ink + 점 규칙이 지켜진다.
- 커뮤니티 댓글: 밀도와 여백이 목업 수준이다.

남은 것은 기본 크기에서 보이지 않는 마감 문제다. 접힌 BEST 아래 스레드, 접근성 글자 크기(AX5)에서 VS 화면이 가로로 넘치는 문제, 그라디언트 예산 위반 1곳이다.

## 3. 남은 must-fix (3건)

### R2-1. 접힌 BEST 자리 아래 "주인 없는 답글"
- **현상**: `max-*-community-comments`, `max-dark-community-replies`에서 `↑ BEST로 올라간 댓글 · 펼치기` 바로 아래에 `@피파탐색이 …` 답글 2개와 `답글 3개 더 보기`가 붙는다. 두 번째 접힘 아래에는 `보엠(작성자) @신카레49 …`가 붙는다. 접힌 줄에 작성자 정보가 없어서, 이 답글들이 바로 위 `몽키스패누` 댓글의 답글처럼 읽힌다.
- **원인**: `PostDetailView.swift:483-492`에서 루트가 BEST면 `bestPlaceholder`만 그린다. `t.replies`는 평소처럼 그 아래에 렌더된다.
- **변경**(둘 중 하나)
  - **A(권장)**: 접힌 줄에 주인을 밝힌다. 22pt 틴트 아바타 + `피파탐색이 · BEST로 올라간 댓글 · 펼치기`(13pt faint)로 쓰고, 답글 들여쓰기 연결선의 시작점이 이 아바타에 닿게 한다. 그러면 스레드 구조가 유지된다.
  - B: 루트가 BEST인 스레드는 답글까지 함께 접는다. 문구는 `… · 답글 N · 펼치기`다.
- 완료 기준: 재캡처에서 모든 답글의 부모가 화면 안에서 식별된다.

### R2-2. VS — AX5에서 화면이 가로로 넘친다
- **현상**: `se-ax5-dark-vs`에서 `보엠 vs 팔디` 제목, 설명, 검색 카드, `비교` 버튼이 화면 좌우로 잘린다. 스크롤 콘텐츠 전체가 화면보다 넓다.
- **원인(추정)**: `VersusCompareCard` 머리 HStack(`VersusView.swift:251-268`)의 폭이 줄지 않는다. 구성은 `side(A)`, `.fixedSize()`가 걸린 가운데 점수, `side(B)`다. AX5에서 `FormTierButton` 알약 2개와 36pt 점수가 375pt를 넘으면, 부모 VStack까지 넓어진다.
- **변경**: `typeSize.isAccessibilitySize`일 때 머리를 세로로 쌓는다. 순서는 A 줄(이름 + 알약), 가운데 `이긴 항목 0 · 5`, B 줄이다. 또는 `ViewThatFits { HStack… ; VStack… }`를 쓴다. 이름 옆 `최고 챔피…`에는 이미 말줄임이 있으니 알약에만 `.lineLimit(1).minimumScaleFactor(0.8)`을 준다.
- 완료 기준: `se-ax5-dark-vs`에서 좌우 16pt 여백이 보이고 가로로 잘리는 글자가 없다.

### R2-3. VS — 한 화면에 그라디언트 2개
- **현상**: 비교한 뒤에도 `비교` 버튼(그라디언트)과 `VS 카드 스토리로 공유`(그라디언트)가 한 화면에 함께 있다. "그라디언트는 화면의 주 CTA 1개" 원칙을 지키지 않은 유일한 화면이다(1라운드 §5).
- **변경**: 결과가 있으면 `비교`를 보조 스타일로 내린다(`FC.surface2` 채움 + `FC.tint` 15SB). 결과가 없을 때만 그라디언트로 둔다. 입력값이 마지막 비교 닉과 다를 때 다시 그라디언트로 올리는 것은 선택 사항이다.
